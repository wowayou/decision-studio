# 界面与底层重构（2026-11-23）

目标：在不改变决策语义的前提下，让界面更易读、更一致，并加固数据安全和运行边界。规则包 `1.0.0`、项目格式 `1`、导入校验规则都没有变；旧备份可以直接导入。没有新增 P1/P2 能力、AI、远端服务或运行时依赖。

## 做了什么

### 视觉系统与界面

- **设计令牌**（`src/styles/tokens.css`）：语义颜色、7 级字号令牌（12–26px，另有窄屏标题 22px、欢迎标题 24px 两个固定值）、4px 间距、圆角和阴影。20 组主要文字/背景令牌组合按 WCAG 公式计算均 ≥ 4.5:1；图节点状态色条非文字对比度 ≥ 3:1。删除了 `!important` 补丁块；剩余的 `!important` 只用于打印、减少动态效果、错误输入框，以及覆盖窄屏下由脚本写入的侧栏高度。
- **12px 字号下限**：任何可见文字不小于 12px，正文 14px，题目 20px。浏览器测试会在桌面和 375px 下逐视图检查。
- **样式拆分**：`tokens → base → shell → views` 四个文件，替换原来 360 行的单文件。
- **框架**：去掉伪面包屑与英文 eyebrow。顶栏吸顶，显示保存状态与导入/导出；页面标题带当前视图名称和一句说明。窄屏时 4 个视图在一行内，“场景模板”移到品牌行右侧，顶部按钮 ≥ 44px。
- **决策进度**：用进度条和“全部关键决策”展开列表，替换原来的两条横栏，所有视图共用。题号按引导顺序显示（“第 1 / 7 题”），只统计当前适用的问题。
- **题卡**：推荐选项直接带“建议”标签；选“尚不确定”时说明它不等于“不需要”；预算输入框带单位。
- **方案页**：新增可评估方向的对比表，覆盖硬条件、维护、扩展、成本、取舍和维护责任，只用离散等级。卡片网格自适应列数；规则 ID 收进“适用前提与规则依据”。
- **依赖图**：状态图例；节点左侧状态色条配合状态文字；画布高度按内容计算；标题单独占一行，避免被截断。
- **页内确认对话框**（`ConfirmDialog`）：替换三处 `window.confirm`，默认焦点在“取消”，关闭后焦点回到触发按钮。
- **导出菜单**：可用 Escape 或点击外部关闭，菜单项说明 JSON 与 Markdown 的用途。

### 底层加固

- **多标签页保护**（`useLocalProject`、`storage/browser.ts`）：另一个标签页修改或清空项目时，当前页暂停自动保存，由用户选择“载入最新版本”或“保留此页并覆盖”。每次写入前还会比对存储是否仍是本页上次看到的内容，所以即使错过了事件（标签页被冻结、从往返缓存恢复）也不会静默覆盖。比较只看项目事实，忽略导出时间和派生结果，所以仅打开第二个标签页不会误报。内容相同的项目不重复写入。
- **渲染失败兜底**（`ErrorBoundary`）：显示恢复页，可下载本机原始项目，不写存储。
- **生产 CSP**（`vite.config.ts`，仅作用于构建产物）：`default-src 'none'`、`script-src 'self'`、`connect-src 'none'`、禁止 `eval`。页面因此无法向任何地址发起连接。
  - 冒烟测试发现 Zod 4 会用 `new Function` 探测能否 JIT 编译，引发 CSP 违规。现已显式设为 `jitless`，没有放宽策略。CSP 环境下 Zod 本来就会回退到解释执行，所以校验结果不变。
- **标识生成回退**（`core/id.ts`）：非安全上下文没有 `randomUUID` 时，用 `getRandomValues` 生成符合 RFC 9562 的 v4 UUID。
- **输入边界一致**：`TEXT_LIMITS` 由界面、校验和导入共用。超过 2000 字的需求描述在创建时就拒绝，不再产生导出后无法导入的备份。
- **分层**：`storage/project.ts` 只做纯序列化和校验，浏览器副作用放在 `storage/browser.ts`。只读查询（可编辑性、上游问题、进度）移到 `domain/inspect.ts`。`App.tsx` 拆成 Shell、引导、记录、模板、提示等组件，编辑、草稿和焦点语义保持不变。
- **下载**：先把链接挂到文档上再点击，提高跨浏览器兼容性；延迟释放 Blob。
- **更严格的 TypeScript**：`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`noImplicitReturns`、`noImplicitOverride`、`noFallthroughCasesInSwitch`。启用后发现并修正 12 处可能的 `undefined` 访问，以及一个不可靠的类型守卫：`editableQuestion` 对 `identity` 返回 false，却声明为 `id is Qid`。
- **测试卫生**：生产冒烟截图改写到 `test-results/`，不再覆盖已提交的历史证据。E2E 总超时随用例增加改为 360 秒。

新增浏览器用例覆盖：

- 导入替换与清空的页内确认（取消不改动存储，Escape 后焦点回到入口）。
- 双标签页冲突：暂停保存、确认后载入、明确覆盖。
- 错过 `storage` 事件时的写入前比对。
- 渲染失败恢复页下载的内容与存储原文一致。
- 导出菜单的键盘操作。
- 桌面与 375px 下各视图都没有小于 12px 的可见文字，也没有横向溢出。
- 窄屏导航保持一行、名称完整，顶部按钮触控尺寸 ≥ 44px。

过程中实际出现、已修复的问题（没有放宽任何检查）：

1. 首次完整 E2E 有 1 项失败：375px 下 500 字符的“其他情况”撑宽页面。根因是窄屏网格列使用 `1fr`（最小值为内容宽度），已改为 `minmax(0, 1fr)`，并在全局开启长词换行。
2. 首次生产冒烟失败：Zod 的 `eval` 探测触发 CSP 违规（见上文），已设为 `jitless`。
3. 截图走查中发现：图节点标题被状态标签挤压截断；“本次更新”标记换行压住标题；窄屏修订号折行；去掉 `!important` 后模板卡链接因选择器优先级不足失去强调色。均已修正，并重新截图确认。

### 独立审查

另一个只读子代理审查了完整 diff。它运行了类型检查和单测，没有发现高严重度问题，确认确认框、保存状态与 StrictMode 双重执行路径正确。中、低严重度的发现与处理如下：

- **中：自动保存只依赖 `storage` 事件。** 标签页被冻结或从往返缓存（bfcache）恢复时会错过事件，进而静默覆盖。已改为写入前比对存储内容，并补充变异验证过的用例。
- **低：“载入最新版本”可能载入打开对话框之前的旧快照。** 已改为在真正载入时重新读取存储。
- **低：载入会静默丢弃本页暂停期间已应用的修改。** 现在会先确认，并提示先导出备份。
- **低：冲突期间清空时，文案没有提到另一个标签页的版本。** 已补充文案。
- **低：未恢复备份的下载用的是启动时快照。** 保留现状：这份快照正是那份无法恢复的原始项目唯一的副本。

## 仍有边界

- 只在 Chromium 上测试过；没有做 Firefox/Safari 验收、屏幕阅读器完整走查，也没有新手可用性研究。截图、对比度计算和自动化测试不能证明可用性或转化率。
- 多标签页保护只覆盖同一浏览器、同一来源，依靠 `storage` 事件加写入前比对。比对和写入之间没有加锁（localStorage 不提供原子的比较并交换），两个标签页在同一瞬间写入仍可能互相覆盖；单用户本机场景下，这个概率被视为可接受。
- CSP 由 meta 标签注入：`frame-ancestors` 和报告上报无法用 meta 设置，托管部署时需要另设响应头。开发服务器不启用 CSP。
- 草稿仍只保存在内存里，不跨刷新保留；这一行为与重构前相同。
- 依赖安装时，本机 npm 缓存缺少 `zod-4.3.6`，因此用 `npm ci --prefer-offline` 按锁文件从公共 npm 源补齐。没有新增或升级任何依赖，也没有运行线上漏洞查询。
