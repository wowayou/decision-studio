# UX 走查与局部优化

> 历史记录：本文描述 2026-11-22 的节点编辑优化。之后的视觉系统、页面结构与加固见 [REFACTOR.md](REFACTOR.md)，其中的界面截图与测试数量以该文为准。

本次目标：降低「找到节点 → 改条件 → 看懂重算 → 继续原任务」的操作成本，不改规则、硬约束、来源、项目格式，也不新增 P1 双图、历史撤销或 AI。

## 优化前：实际浏览器证据

2026-11-22，在现有本机 5173 服务用全新 Chromium 上下文走查（1440×900，不操作用户浏览器数据）：

- 选择访客账户后，节点依据顶部在 y=1038，修改按钮在 y=1282，均超出首屏。
- 图内修改强制跳到引导；确认后显示内容维护者，而不是继续当前节点任务。
- 重新进入图，选中节点重置为本期账户能力。回到同一已更新节点需 6 次控件操作、2 次视图切换。
- 进入编辑与确认后的焦点均落在 BODY，没有上一题和本次变化摘要。
- 源码复核：草稿只在题卡内部；选择、接受建议与未知的提交边界不统一；失效提示仅依赖最后一条日志。

证据：[走查记录](evidence/ux/before-walkthrough.json)、[桌面图](evidence/ux/before-graph.png)、[移动图](evidence/ux/before-mobile-graph.png)。点击数是固定脚本的操作计数，不是用户研究或效率提升承诺。

## 成熟模式与取舍

- 实际阅读 [GOV.UK Check answers](https://design-system.service.gov.uk/patterns/check-answers/)：修改时预填原答，完成后返回检查上下文，不重走其余流程。借鉴定点编辑，不照搬政务申请的强制最终提交。
- 实际阅读 [W3C 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：对话框限制焦点、Escape 可关闭、结束后回到合理入口。使用原生 dialog，不引入弹窗框架。
- 采用 Inspector（属性检查侧栏）：桌面把输入与依据放在图旁，窄屏以对话编辑避免两列挤压。侧栏会占画布宽度，因此保留横向滚动、文字入口和可收起的详情，而不是缩小文字追求完整图形。
- 不宣称走查过 Figma/Linear/Carbon 的真实产品交互；Carbon 正文未取得，未将其作为实施证据。独立 UI/UX 审查与本机源码、真实走查相互核对。

已实际阅读的公开文档摘录：[reference-excerpts.txt](evidence/ux/reference-excerpts.txt)。不套用营销表单技能中的转化率、完成率经验数字，本产品目标是编辑任务与决策正确性。

## 实施切片

1. **上下文**：图节点原位编辑，选中状态放在工作台层；任意决策清单/记录可定点修改并返回原视图。新下游待确认项有直接入口，但不强迫重走引导。
2. **草稿边界**：所有选择先成为未应用草稿；只有「确认并继续 / 应用修改」提交。建议仅填入选项；未知不等于否。取消不改项目，切走未应用草稿须明确处理。
3. **结果反馈**：用真实求值前后快照生成影响预览与本次变化摘要。区分参与重算、实际结果改变、仍兼容的确认值、候选条件/次序变化、冲突/失效。重算、应用与本机保存是不同状态。
4. **引导与访问**：上一题只是导航，不撤销事实；新题聚焦标题；编辑应用/取消恢复入口焦点；移动提交操作可达，顶部可直接查看当前草案。

## 验收约定

保持已有规则单测和 P0 回归；新增真实浏览器用例验证原位修改、取消/草稿不入导出、预览与实际一致、返回原节点与视图、上一题不改修订、未知、冲突、持续失效提示、存储失败、键盘与移动对话。运行后在此记录实际结果与仍未验证事项。

## 实施结果与验收

已完成本次局部优化，并在同一任务上重新走查：

| 指标（1440×900 固定任务） | 优化前 | 优化后 |
|---|---|---|
| 从图选择访客账户、改为无需账户、回到同一已更新节点 | 6 次控件操作 | **3 次**（点节点、选答案、应用） |
| 被迫切换视图 | 2 次 | **0 次** |
| 应用后的选中节点 | 回图重置 membership | **保持 login** |
| 应用后的焦点 | BODY | **原节点** |
| 编辑/应用操作可达性 | 编辑入口 y=1282，需滚动 | 直接点节点；应用按钮 y=826、高44，位于900px视口内 |

这只是固定走查任务的操作计数，不代表用户理解、平均任务时间或整体可用性提升比例。优化后的记录：[after-walkthrough.json](evidence/ux/after-walkthrough.json)。

- 原位编辑与原上下文返回：图旁/窄屏对话框；从能力节点调整上游也回到原能力。
- 单一提交边界：建议、选项、未知都是草稿；预览不写入项目。取消、放弃、继续编辑都有明确语义。
- 本次影响：实际前后求值对比，包括答案来源、重算集合、实际变化、保留项、方案条件与次序；稳定以名称/规则ID识别方向，不用临时 A/B/C 当身份。
- 引导：上一题、先看方案、已应用草案导出；回看/相同已确认答案不重复追加修订。
- 持续提醒：失效基于当前状态，修改无关输入不会隐藏。再次启用账户也需重新确认原答。
- 保存阶段：应用、结果更新、本机保存分开反馈；窄屏保存失败也可备份。

## 仍有边界

- 草稿只在内存，不跨刷新/关闭保存；界面与 README 明确标注，刷新前请先应用。没有冒充自动保存草稿。
- 仅测试 Chromium；未做人工新手任务研究、完整屏幕阅读器/200%缩放审查或其他浏览器验收。
- 本次点击数、焦点与布局检查不是转化率或普遍易用性的证明。
- 网站方案的费用、许可与扩展兼容性仍待核实，不能据此直接上线。AI/P1/P2、双图和历史撤销未开启。
