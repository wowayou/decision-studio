# P0 演示与复现（含本次 UX 优化）

按 README 运行 `npm run dev`，在 `http://127.0.0.1:5173` 打开。所有决策与输出在本机运行，不需要 AI、API Key 或外部服务。

## 1. 只选模板就有草案

- 点击「B2B 多语言官网」。立即看到内容维护问题和方案草案。
- 勾选只是模板预填，不是用户确认；每题有注释、系统推荐理由、不确定和其他情况。
- 点「确认并继续」接受当前选项。推荐与当前选项不同时，可以「填入建议」，然后确认。
- 可以直接「先看方案」。方向明确区分满足已知硬条件与前提待核实，组件都有来源。

## 2. 多选与未知

- 内容维护者同时选择「运营同事」「开发人员」，再确认并继续。
- 对访客账户选择「尚不确定」，再确认。系统保留未知，不转换成无需账户。
- 可以继续回答、上一题回看，或提前查看/导出草案。上一题不会撤销已应用事实。

## 3. 在图上就地修改与看懂重算

- 到「决策依赖图」，直接点「访客账户」输入节点。
- 桌面在图旁编辑，窄屏用对话框。改为「现在需要」，先看「应用前预览」。此时方案与本机保存仍对应旧答案。
- 点「应用修改」：仍留在当前图与节点；摘要说明认证、数据、部署和可评估方向的变化。
- 点「查看本次变化与保留项」了解规则影响。已确认的语言、内容编辑角色不会被改写。
- 也可选择规则节点，例如账户数据，从「影响它的条件」直接调整访客账户，应用后仍回到该能力。
- 修改已确认答案时，若内容完全相同，应用按钮不会无意义地追加修订；可取消返回。

## 4. 失效原答保留

- 在「全部关键决策」或图上，先确认本期需要账户，再确认一种登录方式。
- 改成「无需访客账户」。原登录方式标为失效，原值保留。
- 修改语言等无关输入，提醒仍保留。
- 重新启用账户后仍需确认原登录方式；可从提醒或变化摘要直接进入确认，不强迫重走其余引导。

## 5. 草稿、取消与键盘

- 更改任一选项但不提交：只有草稿和预览改变，不写入项目、记录或导出。
- 点取消或按对话框 Escape，返回原入口，不改已保存事实。
- 有未应用修改时切换视图，会询问继续编辑或放弃并离开；继续编辑会保留输入。
- 键盘 Tab 可遍历控件，Enter/Space 操作；换题聚焦标题，对话框首末控件循环并在关闭后恢复焦点。
- 草稿不跨刷新保存，刷新前请先应用。

## 6. 范围与不可妥协的条件

- 在全部决策打开月预算：目标下限 100、目标上限 300、可容忍上限 500，应用后导出 Markdown。
- 报告保留两段区间，成本仍待核实，不宣称符合预算。非法范围保留输入并定位错误字段。
- 修改维护偏好只影响合格组的展示次序，不抵消硬约束。
- 先备份，再切换到硬约束冲突示例。要求账户又禁止访客账户资料时，没有可继续评估的方向；软偏好不能绕过。
- 明确取消冲突限制并应用后，只显示实际剩下的方向，扩展权限仍有待核实标记。

## 7. 保存、恢复与失败

- 顶部本机保存提示对应已应用数据；刷新恢复答案和来源。
- 导出 JSON → 决策记录中清空并确认 → 导入同一文件，原答、约束、候选、版本与记录一致。
- 配额失败时，数据可能已应用但尚未保存；按提示导出。窄屏图详情也提供 JSON 备份按钮。
- 保持本机服务可断外网使用。自动化也验证页面加载后阻断全部网络；不承诺关闭服务后的冷启动缓存。

## 自动复现与 seed

- `npm test`：规则、输入、恢复与草稿/影响投影单测。
- `npm run test:e2e`：原 P0 场景加原位修改、返回、取消、持续失效提醒、移动键盘与保存失败。
- `npm run test:smoke`：构建后检查生产版本与响应式布局。
- seed 位于 `src/domain/website.ts` 的 `fixtures`：`b2b-site`（含未知）、`blog`、`saas`、`contradiction`。

这些步骤是可操作演示，不替代用户研究。P1/P2 与 AI 仍未开启。实际结果见 `docs/UX_REVIEW.md`。
