# Decision Studio · P0

面向普通用户的网站架构选型工作台。选择场景、确认少量有注释的关键条件，即可得到带来源和假设的动态方案草案。**规则优先、无 AI 依赖，不会创建真实网站或部署资源。**

## 安装与运行

需要 Node.js ≥22.12；实际验收环境为 Node.js 24.18.0 / npm 11.16.0。

```bash
git clone https://github.com/wowayou/decision-studio.git
cd decision-studio
npm ci
npm run dev
# 浏览器打开 http://127.0.0.1:5173
```

```bash
npm run build
npm run preview
# 本机预览生产构建，默认 http://127.0.0.1:4173
```

开发与预览默认仅监听本机回环地址。没有账号系统、后端服务、远端数据库、云同步或 AI 密钥配置。此实现不需要设置任何环境变量。

本次依赖全部通过本机 npm 缓存离线安装，浏览器也使用既有 Chromium 缓存；没有调用付费 API 或创建远端资源。`package-lock.json` 固定依赖，Rollup/PostCSS overrides 用于固定可用的兼容缓存版本。没有运行线上依赖漏洞查询，不能据此声称依赖没有漏洞。

## P0 可用能力

- 场景：B2B 多语言官网、个人博客、带账户的 SaaS 网站，以及故意冲突的演示项目。
- 8 个输入决策：用途、编辑角色、访客账户、登录方式、语言、硬性限制、预算范围、维护/扩展偏好。另有 6 个规则能力节点。
- 默认逐题引导，始终可预览草案。可填入建议、多选、填写预算区间、保留未知、选择其他情况，并返回任一可回答问题。
- 3 个受规则约束的架构方向：静态内容站、托管内容管理站、应用型网站。不是任意组件组合，不强行补足方案数量。
- 交互式依赖图、文字依据和原始输入来源；图不存独立的业务事实。
- 本机自动保存、刷新恢复、JSON 备份/导入、Markdown 草案导出、输入与传播记录。

当前技术默认值属于规则包的起步建议：Astro + 可选 Decap CMS；WordPress + 内容数据库；Next.js + 可选内容后台、账户认证与数据库。每个组件都有通俗解释和组合规则来源。这些**不是已经验证可上线的服务套餐**，也不承诺具体软件版本、费用、许可或服务商能力。

## 决策与约束语义

1. 原始输入保留 `value / status / source / reason / updatedAt`。模板默认不等于用户确认；主动选择未知仍然记录用户来源，但不变成“不需要”。需求原文只保存供核对，**没有偷偷做 AI 提取或关键词猜测**。
2. 网站依赖表编译为 DAG（有向无环图，保证求值不会循环）。每次编辑只重算该字段及后继能力，复用其余节点，然后重建候选与报告。
3. 本期账户条件改变后，不适用的用户登录方式标为 `stale` 并保留原值。重新启用账户也不会自动升格为已确认，必须明确确认。
4. 硬约束冲突会阻塞所有方向。例如“本期必须提供账户”与“禁止存储访客账户资料”，或“本期无需账户”与“本期必须账户”。软偏好不能抵消违规。
5. 候选明确区分 **满足已知硬条件 / 前提待核实 / 已排除**。前两者都仍是有条件草案；已排除方向只在排除原因中显示。
6. 维护、扩展、成本使用好/有取舍/弱/待核实等离散指标；先按可行性分组，再按偏好排序，同档并列，不提供伪精确分数。
7. 预算记录目标区间与可容忍上限。没有实时报价，填预算后成本适配仍待核实，不能断言满足上限。CMS 会员权限和企业身份集成兼容性同样待核实。
8. 复杂交易/定制业务显示规则覆盖不足，不输出确定性完整架构。未来账户需求只列入后续阶段，不自动加入当期组件。

## 节点修改与草稿（本次 UX 优化）

- 桌面点输入节点就在图旁编辑；窄屏打开对话框，不跳回引导。规则节点可以直接调整其上游条件。应用后保留原视图与所选节点。
- 选项、建议和未知都先修改草稿，只由「确认并继续 / 应用修改」提交。未应用草稿不影响方案、记录或导出；切换有修改的上下文时可继续编辑或放弃。
- 影响预览与本次变化摘要来自同一规则引擎的前后结果，明确区分参与重算与实际改变，并解释候选条件/次序与保留的确认值。没有强行生成唯一赢家。
- 引导有上一题与继续；回看不是撤销，已确认相同答案不会重复产生修订。模板默认接受为确认则仍保留来源升格记录。
- 错误保留输入并定位到字段。对话框支持键盘循环、Escape 取消及返回入口；登录方式失效提示依据当前状态持续展示。
- 数据应用与本机保存是两回事。保存失败会提示，窄屏详情内也可直接导出当前已应用数据。
- 草稿只在内存中，不跨刷新/关闭保存；请先应用答案再刷新。选中节点跨视图保留，但不作为项目事实导出。

详细参考、真实走查与证据见 `docs/UX_REVIEW.md`。没有新增双图、历史撤销、AI 或其他 P1/P2 产品能力，项目格式和领域规则版本保持不变。

## 保存、导入与导出

- 一次维护一个项目，使用 localStorage 单键原子写入。清除浏览器数据、私密模式退出或换浏览器可能丢失本机项目，**JSON 才是可携带的备份**。
- 切换模板、清空或导入替换前使用页内确认对话框，默认焦点在「取消」；取消不改动本机项目。保存配额/权限失败会明显提示，内存中的草案仍可导出。
- 同一浏览器打开多个标签页时，若另一个标签页修改或清空了项目，当前页**暂停自动保存**并提示「载入最新版本 / 保留此页并覆盖」，不会静默互相覆盖；每次写入前也会核对存储内容，错过事件（如标签页被冻结）时同样暂停。仅打开第二个标签页不会触发提示。
- 界面渲染出错时显示恢复页，可直接下载本机保存的原始项目；恢复页只读，不写存储。
- 导入/导出上限为 **4 MiB（UTF-8 字节）**。超限变更不应用，保持现有可备份项目；文件在读取和解析前后都有大小保护。
- 项目格式为 `1`，网站规则包为 `1.0.0`。导入检查类型、选项、区间、版本、来源与变更记录，并通过记录重放恢复事实。
- 备份内的候选和图节点不是权威事实，恢复时重新计算。不要手工修改答案或来源而不更新记录；来源/记录不一致会拒绝导入。
- 版本不匹配时拒绝静默迁移，并保留原始本机备份下载入口。已有迁移入口，但第一版只支持当前格式；规则/模板变化应升级规则包版本并明确迁移政策。
- Markdown 包含执行摘要、已确认/模板/未知/失效状态、能力来源、组件、取舍、排除理由、维护责任、待核实事项、分期及实施清单。始终标为有条件草案。

## 离线与 AI 边界

安装依赖后，可在不联网的电脑上通过本机服务运行；运行中所有求值、编辑、图、保存和导出都不需要外部网络。浏览器自动化还验证了**资源加载后阻断全部网络**的核心操作。

生产构建（`npm run build`）在页面中注入内容安全策略（CSP）：只允许加载同源脚本与样式，`connect-src 'none'` 禁止页面发起任何网络连接，也禁止 `eval`。开发服务器不注入，以免阻断 Vite 热更新。若将来托管到服务器，还应以响应头设置 `frame-ancestors`（meta 标签无法设置）。

没有 Service Worker 或安装型离线缓存：完全断开本机 HTTP 服务后，不能承诺关闭页面再冷启动/刷新仍然加载成功。保持本机服务，或先加载页面再断外网即可使用。

本版没有 AI 调用入口，也不向第三方上传需求。AI 提取、审查、结构化补丁及调用限额属于 P1，尚未实施。因此也没有 AI 自动覆盖用户确认值或硬约束的代码路径；未来接入必须单独落实提案校验、模拟变更与逐项授权。

## 测试

```bash
npm test          # Vitest：纯规则、传播、冲突、来源与持久化
npm run test:e2e  # Playwright：真实 Chromium 核心操作
npm run build    # TypeScript 检查与生产构建
npm run test:smoke # 构建后在本机预览真实 dist：4 个响应式宽度、CSP 违规、页面错误与外部请求
```

其他机器首次跑 E2E 需要 Playwright 的 Chromium；没有浏览器缓存时，可由使用者执行 `npx playwright install chromium` 下载浏览器。本次未执行下载或系统级安装。

E2E 为单 worker、无自动重试、总超时 360 秒；生产冒烟测试另限 30 秒。两者不添加 CI、周期任务或远端测试服务。图片与 HTML 报告生成于 `test-results/`、`playwright-report/`；验收时保留的实际输出见 `docs/evidence/`。测试不等同于新手可用性研究或生产可靠性证明。

## 文件结构与技术取舍

```text
src/core/           类型、会话变更、依赖编译、标识生成
src/domain/         网站问题、4 个 seed、规则、候选、报告与只读查询（inspect）
src/storage/        project：Zod 校验、版本入口、恢复、备份（纯函数）
                    browser：localStorage、跨标签页事件、下载（浏览器副作用）
src/ui/             App 编排；AppShell、GuideView、DependencyGraph、Solutions、RecordView 等视图
                    useLocalProject：已应用项目与本机保存状态的唯一来源
src/styles/         tokens（颜色/字号/间距）→ base（元素与按钮）→ shell（框架）→ views（各视图）
vite.config.ts      仅生产构建注入 CSP
tests/unit/         规则、边界、保存、局部重算基线与加固项
tests/e2e/          真实 Chromium 验收场景（P0、UX、加固）
```

从只有两份需求文档的目录开始，没有已有技术栈或 Git 仓库。采用 React + TypeScript + Vite；React 状态足够维护单项目，不引入额外状态库。原生 SVG 连线与 HTML 按钮足够呈现 14 节点，避免让图形库承担求值。单项目体量有硬上限，localStorage 满足 P0，保留失败提示和 JSON 备份，不为本地闭环增加数据库服务。Zod 用于不可信导入，Vitest/Playwright 分别验证规则和真实界面。
